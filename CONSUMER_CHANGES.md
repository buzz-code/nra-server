# Consumer Changes

Commits in this repo that don't work automatically after a `server/shared`
submodule bump — each needs a matching change in the consuming app.

| Commit | Adds | Per-app action | Done in |
|---|---|---|---|
| `393e9ad` | S3Module now global in `BaseNraAppModule` | Add `@aws-sdk/client-s3` to `server/package.json`; it needs Node >=20, so also bump `server/Dockerfile`'s `FROM node:16-alpine` to `node:20-alpine` (all 3 stages) if not already there | all 5 apps |
| `c0cd9fe` | `bootstrapNraApplication` now sets `keepAliveTimeout` (35s) and `headersTimeout` (36s) on the underlying HTTP server, to avoid Caddy reusing a keep-alive connection Node already closed | Add `caddy.reverse_proxy.transport: http` and `caddy.reverse_proxy.transport.keepalive: 30s` labels to the `server` service's `deploy.labels` in `docker-compose-swarm.yml` (must stay below Node's 35s `keepAliveTimeout`) | react-admin-nestjs, event-management-nra, teacher-report-nra, student-report-nra, dnd-management-nra |
| (docs) | Relaxed the "never modify `client/shared`/`server/shared` directly" rule in `AGENTS.md` to "avoid when possible" — editing shared code is fine when a change genuinely belongs there | Update the same line in your own `AGENTS.md`/`CLAUDE.md` to match, so all consuming apps stay aligned on this policy | dnd-management-nra, react-admin-nestjs, teacher-report-nra, student-report-nra, event-management-nra |
| `8ffe995` | `handle-email` webhook now guarded by `MailWebhookGuard` (checks `X-Webhook-Secret` header against `MAIL_WEBHOOK_SECRET`); Yemot gets a second, per-user-token-secured mount at `/yemot/handle-call/:secret` alongside the existing open one | Set `MAIL_WEBHOOK_SECRET` in `server/.env` and have n8n send that value as `X-Webhook-Secret` on its request to `handle-email` (no-op / stays open until this is set). No env var needed for Yemot — the per-user token is generated automatically and shown on the client's Tutorial page once `nra-client`'s matching change lands; users need to update their `ext.ini` to the new URL (old one keeps working during migration) | all 5 apps |
| `28a61f5` | `TestAppHelper` now wires `cookie-parser` itself; `utils/testing/e2e/test-utils.ts` adds `registerAndAuthenticate()` (register a test user + guarded Authentication-cookie extraction) and `asList()` (normalizes a CRUD list response that may be a plain array or `{ data: [...] }`) | Not required to keep working (purely additive), but each app's `server/test/*-crud.e2e-spec.ts` should swap its hand-rolled `Test.createTestingModule`/cookie-parser/cookie-regex/teardown boilerplate for `createTestApp()` + `registerAndAuthenticate()` + `asList()` to drop the duplication | react-admin-nestjs, event-management-nra, teacher-report-nra, student-report-nra, dnd-management-nra |
